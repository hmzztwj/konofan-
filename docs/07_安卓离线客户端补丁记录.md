```bash
export MSYS_NO_PATHCONV=1                      # 否则 adb 把 /storage/... 改写成 Windows 路径

$ADB forward tcp:9224 localabstract:webview_devtools_remote_$PID

python tools/cdp.py click 238 178              # 页面 CSS 坐标（1098×618，dpr 1.75）
$ADB exec-out screencap -p > shot.png          # 真实画面
```

两个必须记住的坑：

1. **`Page.captureScreenshot` 会返回陈旧帧**（改背景后 md5 都不变），一律用
   `adb exec-out screencap -p` 才是当前画面。
2. **沙箱内 adb 起不来 daemon**（`CreatePipe failed: 拒绝访问。(5)`）：需要用一次
   `danger-full-access` 跑 `adb start-server`，之后同机的 adb 客户端（只连 5037）就正常了。

排错工具：

- `tools/cdp_net.py` —— 开 Runtime/Log/Network，可选先派发点击，抓 4 秒内
  4xx/5xx、loadingFailed、console 错误（**定位 404 资源的第一选择**）。
- `tools/cdp_which.py` —— 对单个 URL 打一次 fetch，打印 Network 事件里的
  `fromDiskCache / fromServiceWorker / initiator`，用来判断「这个响应到底是谁给的」。

## 1. 教团招募：`Cannot read properties of undefined (reading 'guild')`

首页左上弹「教团招募 / Cannot read properties of undefined (reading 'guild') / 重新读取」。

抓 `assets/main-Ct99tHOY.js` 的导出表：

```js
X  = (e,t={}) => O('POST', `/guild/${e}`, t)
Xa = async () => (await X('home')).home          // 导出成 m
Za = async (e,t={}) => { let n = await X(e,t); return {home:n.home, joined:n.joined} }
```

`assets/net-BFZHtxYd.js` 的请求函数只做「fetch → json → 非 2xx / ok:false 抛错」，
**成功时原样返回响应体，不剥 `data`**。招募卡 `assets/guildAds59-*.js` 里：

```js
x = e => e?.config.ads ?? a
let t = await h();            // h = Xa
if (this.home = t, !x(t)?.adsOpen || t.guild) return this.conceal();
```

所以旧桩回 `{status:0, data:{guild:null,...}}` 时，`.home` 是 undefined，`t.guild` 正好抛这句。
**正确形状是扁平的**：

```js
{ home: { guild: null, config: { ads: { adsOpen: false, ... } }, ... } }
```

`patches/site/__kf_lot.js` 里已按此实现 `guildHome()` / `guildPayload(ep)`，
并给其它 `/api/guild/*`（list/applies/logs/faith/ads/warehouse/grants/recruit/duel…）
统一兜底；同时修掉了 `function six()` 重复声明导致买票号码变成 `NaN` 的 bug（改名 `rand6`）。

> 注意：现在真正接管 `/api/lottery/*` 的是 `bridge.js`（见第 3 节），
> `__kf_lot.js` 的彩票分支只是兜底；两者都保留，不冲突。

## 2. 教团 / 商会页：「读取失败，请检查网络后再点一次」

点教团先弹这个提示、停在首页；看起来像网络问题，其实是 **404 了一个 CSS**。

`tools/cdp_net.py click 57 178` 抓到：

```
404 (404, 'http://127.0.0.1:8787/assets/guild59-B6De0oYB.css')
```

机制在 `assets/preload-helper-*.js`：Vite 的 `__vitePreload` 对 `import()` 的
`mapDeps` 逐个插 `<link>`，`.css` 会挂 `load/error` 监听：

```js
if (r) return new Promise((e,n)=>{ i.addEventListener(`load`,e),
  i.addEventListener(`error`,()=>n(Error(`Unable to preload CSS for ${t}`))) })
```

CSS 404 → Promise reject → 动态 import 失败 → 页面外层 catch 显示「读取失败」。
当前构建（`main-Ct99tHOY.js`）缺的 CSS 只有两个：

```
assets/guild59-B6De0oYB.css
assets/imageAnnounce-8fL6REue.css
```

补上占位文件（内容一行注释即可）后，教团页正常显示「教团需要在线登录，和其他玩家一起玩。」，
商会页显示「商会业务需要在线登录，与其他冒险者共同经营。」——都是离线态文案，不再卡住。

## 3. 幸运彩券：「我的彩券」永远空

现象：彩券页能开、四张宣传绘都在、买票成功（`oldui59.save` 的 `x.lotteryTickets`
新增 `{"no":"730283","day":"2026-10-30","ts":...}`），但「我的彩券」一直
「还没有购买记录，回到本期即可购买。」

排查关键：`/api/lottery/home` 返回的是 `{data:{now,round,results,mine,tickets}}`，
其中 `mine: []`、`tickets: []`、`estimate:[1000000,500000,5000000]`，与我们写在
`site/__kf_lot.js` 里的实现（扁平、`estimate:[10000000,...]`、`tickets: tk`）不一致。
再用 `tools/cdp_which.py` 看：这个 URL **根本没有产生 Network 请求**（`hits: 0`），
说明响应在 JS 层就被吃掉了。

对比 md5 后定位到真正接管的文件：

```
site/__bridge.js  ==  android/konofanmgr/assets/bridge.js  (abfb1364…, 17354 B)
```

它开头是一段「彩票本地化补丁」IIFE（**先于主桥接执行**，且在 `site/__kf_lot.js` 之后加载，
所以它的 `window.fetch` 在外层），原来的 `home()` 是：

```js
function home() {
  var s = rd(), dd = day(), mine = mineOf(s, dd);
  return { now:..., round: { ..., myTickets: mine.length, ... }, results: [], mine: [], tickets: [] };
}
```

`mine` 算完就丢了。这一轮把它整个重写（`android-konofanmgr/assets/bridge.js`，
同时推到设备 `site/__bridge.js`）：

- `mineOf(s)` 按 `day` 汇总票根，输出客户端渲染要的字段：
  `roundId / qty / spent / drawAt / status('open'|'settled') / winNo / hits[4] / money / shards`；
- `winNo(dd)` 用 FNV-1a 从日期派生六位号码（不联网也要有「中奖号码」）；
- 命中位数 6/5/4/3 → 一/二/三/四等奖，每张 `1,000,000 / 500,000 / 1,000,000 / 500,000` 艾莉丝，
  碎片 `100 / 30 / 1 / 0`，与页面 `TIER_CASH/TIER_SHARD` 对齐；
- 每天 20:00（`drawAt = dd + 'T20:00:00+08:00'`）之后才结算，之前 `status:'open'`（页面显示「等待开奖」）；
- `roundId` 以 2026-10-24 为第 1 期按天推算，`myTickets` 只算当日票。

验证（截图在 `out/lotcheck/`）：

| 场景 | 结果 |
|---|---|
| 首页 | 无错误框 |
| 教团 / 商会 | 离线态文案，不再「读取失败」 |
| 彩券页 | 4 张宣传绘（logo / 双头像 / 金冠 / 金币）全部渲染 |
| 买 1 张 | 扣 100,000，票号 `730283`（六位，不是 `NaN`） |
| 我的彩券 | 「第7期 · 1张 / 10/30 20:00开奖」+「第6期 · 1张 / 本期未中奖」 |
| 中奖渲染 | 把 10-29 那张改成中奖号 `460971` → 显示「一等奖×1」 |

## 4. 还欠什么

- `bridge.js` 是 APK 资产：直接 push 到 `site/__bridge.js` 只是临时生效，
  **下次安装/复制会被 `assets/bridge.js` 覆盖** → 需要重新 build APK（`android-konofanmgr/build_apk.sh`）。
- 中奖金额只做了展示，**没有真正发进礼物箱**；`/api/lottery/results`（开奖公示）仍返回空数组。
- 教团/商会页的 `/api/guild/*` 目前是空壳兜底，只能看离线文案，不能真加入教团。
