# 05 · 离线化可行性：为什么"改一改就能离线玩"不成立

## 一、白屏的直接原因（已定位）

客户端启动链路：

```
Unity 启动 → 年龄提示页（本地资源，能画）
           → GET https://static.konosubafd.jp/versions/<ver>_<hash>.json   ← 线上还活着
           → 从 JSON 取 api_url / asset_url                                ← 关键：地址是运行时读的
           → 连 https://api.konosubafd.jp/api/…                            ← 域名已 NXDOMAIN
           → 等 → 白屏
```

证据：

- `ping api.konosubafd.jp` → `unknown host`；`nslookup` 无 A/AAAA 记录。
- `debuggerd -b <pid>` 回溯：`UnityGfxDeviceWorker` 停在 `pthread_cond_clockwait`、`UnityMain` 在 `libhoudini`、
  主线程在 `Looper.pollOnce` ⇒ **不是崩溃，是逻辑在等**。
- `dumpsys SurfaceFlinger --list` 只有 Unity 的 `SurfaceView`，没有 WebView ⇒ 白屏是 Unity 自己画的。
- APK 只内置 6 个 bundle：`defaultlocalgroup_unitybuiltinshaders` / `font_assets_all` / `include_assets_all` /
  `storyadvengineassets_assets_all` / `tutorialbattleassets_assets_all` / `tutorialstoryassets_assets_all`。
  标题页与首页 UI 都在 23,069 个远程 bundle 里 ⇒ **连"通信エラー"弹窗都没资源可画**。

## 二、四条路，各自堵在哪

### 路线 A：本地 mock API（试过，卡在 TLS）

- 已完成的：自签 CA + 服务器证书（SAN 覆盖 static/api/agip964t/inquiry/10.0.2.2）、
  `iptables -t nat REDIRECT 443→8443`、`adb reverse`、host 侧 `tools/mitm.py` 能正确返回伪造的 bootstrap JSON。
- 卡点：客户端拒绝我们的证书（`SSLV3_ALERT_CERTIFICATE_UNKNOWN`，30 秒内 19~27 次），
  即使把 CA 同时塞进 `/system/etc/security/cacerts` 与 `/apex/com.android.conscrypt/cacerts`（bind mount，Permissive）。
- 排除项：APK 内没有 `.pem/.crt`；metadata 里没有 `sha256/`、`CertificatePinner` ⇒ 不是证书固定。
- 判断：Unity 原生 TLS 栈（libunity.so 内的 libcurl/UnityTls）用的不是系统信任库。
- 要继续：得 patch `libunity.so` 的证书校验（该 so 未导出 `unitytls_*` 符号，需要先定位校验点），
  或让客户端改走明文 HTTP（版本 URL 字面量已确认有 3 份拷贝，但改成 http 后客户端仍未请求我们，说明运行时用的是第四处拼接）。

### 路线 B：官方 bundle CDN 补齐资源（已确认关闭）

```
GET https://static.konosubafd.jp/bundles/5.7.0/6_LYUotQvoPmrCidgI/<32hex>.bundle  → 403
GET https://static.konosubafd.jp/bundles/5.9.0/cewf8vjh3rscsw88/…                 → 403
GET https://static.konosubafd.jp/versions/5.7.0_….json                            → 200
```

⇒ 只有版本 JSON 还公开，**bundle 目录全部 403**，缺的 20,841 个包拿不到。

### 路线 C：自己重写私服

需要实现的量级（从 `dump.cs` 的 `Wonder.Api.*` 命名空间看）：

- 认证/存档：登录、`LocalSave*`、`MasterallMasterarray`、用户状态同步
- 主循环：首页、抽卡（含保底/演出）、编队、任务、战斗（`battle_wave` 12,856 行数据 + 服务端结算）、
  商店、活动、剧情解锁、好友/公会…
- 每个接口都有对应 DTO，字段名都在 `dump.cs` 里，但**行为语义**（校验、状态机、掉落表）不在客户端。

⇒ 这不是"补几行"，是**从零复刻一个手游服务端**，且每个界面还要有对应 bundle（见路线 B）。

### 路线 D：用官方离线版（现实解）

停服后官方出了 5 个独立离线 App：冒険者ブック、メインストーリー、イベント Part1、イベント Part2、キャラストーリー
（全语音、不含联动）。已知包名 `jp.co.sumzap.pj0016` 等，与 `jp.co.sumzap.pj0007` 不是同一个包。
**想"离线正常游玩"，这才是官方给出的答案。**

## 三、如果一定要继续，最小可行增量

1. **解 TLS**（1~2 天）：静态定位 `libunity.so` 里 `SSL_CTX_set_verify` / `X509_verify_cert` 调用点，
   patch 成恒成功；或在 `il2cpp` 层把 `UnityWebRequest` 的 `certificateHandler` 强制注入总是接受。
   一旦成功，就能看到真实请求序列，`docs/06` 里的 mock 已能接住。
2. **把 bootstrap 指向本地**（半天）：JSON 里 `api_url`/`asset_url` 都换成 `10.0.2.2:8080`，
   客户端就会连我们的服务（这一步是白屏变"有反应"的分水岭）。
3. **补资源**：只能从别的存档/官方离线版里捞，或者接受"只有本地 2,228 个 bundle 对应的界面可显示"。
4. **逐屏做接口**：按 `dump.cs` 的 DTO 一个个填，优先首页→剧情→图鉴。

现实预期：第 1、2 步能到"应用不再白屏、能看到报错/标题"，第 4 步是无底洞。

## 四、当前可直接用的替代品

`site/`（本次生成，不在仓库内）：271 个静态页面，包含 67 个角色、1,030 条剧情条目、266 张数据表、
638 张立绘图、5 章可读剧本 —— **不依赖游戏本体，双击 `index.html` 就能看**。
这是"离线可用"目前的实际形态。
